# Development

This chapter defines the developer expectations for contributing to the project.

## Code standards

- Follow repository linting and formatting rules.
- Keep code readable, explicit, and maintainable.
- Prefer testable abstractions and small units of change.
- Avoid hidden state and undocumented side effects.

## Branching and workflows

- Use a clear branch naming convention.
- Keep branches short-lived and focused.
- Open pull requests early for feedback.
- Require review before merge to main or release branches.

## Testing strategy

- Unit tests for isolated logic.
- Integration tests for cross-service behavior.
- End-to-end or acceptance tests for user-critical flows.
- Run the relevant checks before merging.

## Pull request expectations

- Include a clear summary of the change.
- Link to issue or task references.
- Document risks and rollout considerations.
- Update the relevant documentation when behavior changes.
